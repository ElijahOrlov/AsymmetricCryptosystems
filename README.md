# Асимметричный криптографический алгоритм RSA (Rivest–Shamir–Adleman)

---

## I. Теоретическое описание алгоритма RSA

### Краткая история
RSA — первый асимметричный алгоритм шифрования с открытым ключом, разработанный в 1977 году криптографами Рональдом Ривестом, Ади Шамиром и Леонардом Адлеманом (MIT). 
Название образовано от первых букв их фамилий. Алгоритм стал фундаментом современной криптографии и стандартом для защиты данных в интернете. 
RSA стал прорывом, устранив проблему безопасного обмена ключами в симметричных системах. Несмотря на появление квантовых угроз (алгоритм Шора), он остается актуальным благодаря простоте реализации и проверенной надежности при использовании ключей длиной 2048+ бит.

### Основная идея
RSA использует математические свойства простых чисел и модульной арифметики. Алгоритм позволяет безопасно передавать данные через открытые каналы связи, используя два ключа: **публичный** (для шифрования) и **приватный** (для дешифрования). 
Безопасность алгоритма основана на **сложности факторизации больших чисел**, и обеспечивается тем, что восстановление закрытого ключа из публичного требует разложения модуля на простые множители, что практически невозможно для чисел длиной 2048+ бит. 
Алгоритм оперирует парой ключей: 
- **Публичный ключ** — доступен всем, используется для шифрования.
- **Приватный ключ** — хранится в секрете, применяется для дешифрования.

### Для чего используется?
- **Шифрование данных**: Безопасная передача информации через открытые каналы (например, HTTPS).
- **Цифровые подписи**: Подтверждение подлинности отправителя и целостности сообщений.
- **Аутентификация**: В протоколах TLS/SSL, VPN, электронной подписи документов.

### Математическая основа
1. **Генерация ключей** базируется на выборе двух больших простых чисел `p` и `q`, их произведении `n = p * q` и вычислении функции Эйлера `φ(n)`.
2. **Шифрование** выполняется через возведение сообщения в степень по модулю `n` с использованием публичного ключа.
3. **Дешифрование** требует знания приватного ключа, связанного с обратной операцией в модульной арифметике.

## II. Основные характеристики

| Параметр   | Описание                                                                 |
|------------|--------------------------------------------------------------------------|
| **`p`**    | Большое случайное простое число (≥1024 бит). Секретный параметр, используемый вместе с `q` для генерации модуля `n`. Должно быть уникальным и непредсказуемым. Проверяется на простоту (например, тестом Миллера-Рабина). |
| **`q`**    | Второе большое случайное простое число. Выбирается независимо от `p` с аналогичными требованиями к размеру и случайности. Вместе с `p` формирует основу безопасности RSA. |
| **`n`**    | Модуль, вычисляемый как `n = p * q`. Публичный параметр, используемый в операциях шифрования и дешифрования. Безопасность алгоритма зависит от сложности факторизации `n` (разложения на `p` и `q`). Рекомендуемая длина — 2048+ бит. |
| **`φ(n)`** | Функция Эйлера: `φ(n) = (p-1) * (q-1)`. Секретный параметр, необходимый для вычисления закрытой экспоненты `d`. Знание `φ(n)` позволяет восстановить приватный ключ. |
| **`e`**    | Открытая экспонента. Должна быть взаимно простой с `φ(n)` (т.е. `НОД(e, φ(n)) = 1`). Часто выбирается `65537` как компромисс между скоростью (бинарное представление содержит мало единиц) и защитой от аток. Избегают малых значений (например, `3`). |
| **`d`**    | Закрытая экспонента: вычисляется как `d ≡ e⁻¹ mod φ(n)` через расширенный алгоритм Евклида. Секретный параметр, используемый для дешифрования. Утечка `d` компрометирует всю систему. |
| **Длина ключа** | Размер модуля `n` в битах. Определяет криптостойкость. Минимум — 2048 бит (рекомендовано NIST до 2030 г.). Для долгосрочной защиты используют 3072–4096 бит. Ключи <1024 бит считаются небезопасными. |

## III. Принцип работы и структура алгоритма

Процесс работы алгоритма включает три этапа: **Генерация ключей**, **Зашифрование** и **Расшифрование**.

---

### Этап 1. Генерация ключей  
**Блок-схема**:  
`[Выбор p, q] → [n = p×q] → [φ(n)] → [Выбор e] → [Вычисление d]`

---

#### 1.1. Выбор двух простых чисел 
Два больших случайных простых числа `p` и `q` выбираются с использованием вероятностных тестов (напр., тест Миллера-Рабина). 
Их размер должен обеспечивать стойкость к факторизации.
```
p = 61, q = 53
```

---

#### 1.2. Вычисление модуля `n`
Модуль `n` — произведение `p` и `q`, это публичная часть ключа. Его длина определяет криптостойкость алгоритма (рекомендуется `n ≥ 2048 бит`).
```
n = p × q  ⇒  61 × 53 = 3233
```

---

#### 1.3. Расчет функции Эйлера `φ(n)`
Функция Эйлера необходима для выбора экспонент. Она вычисляется по формуле:
```
φ(n) = (p-1) × (q-1) ⇒ (61-1) × (53-1) = 60 × 52 = 3120
```

---

#### 1.4. Выбор открытой экспоненты `e`
Число `e` выбирают согласно условию:
- `1 < e < φ(n)` - должно быть взаимно простым с `φ(n)`
- `НОД(e, φ(n)) = 1` - взаимно простые числа  

Часто выбирают `e = 65537`, так как это простое число с бинарным представлением `0b10000000000000001`, что оптимизирует вычисления.
```
e = 17   (т.к. НОД(17, 3120) = 1)
```

---

#### 1.5. Вычисление закрытой экспоненты `d`
Закрытая экспонента `d` — модульная инверсия `e` по модулю `φ(n)`.  
Используется расширенный алгоритм Евклида для решения уравнения `e × d + k × φ(n) = 1`.
```
d ≡ e⁻¹ mod φ(n)   ⇒   17 × 2753 mod 3120 = 1   ⇒   d = 2753
```

#### 1.6. Итоговые ключи
- Публичный: `(e=17, n=3233)`  
- Приватный: `(d=2753, n=3233)`

---

### Этап 2. Зашифрование сообщения  
**Блок-схема**:  
`[Сообщение] → [Разбиение на блоки] → [Преобразование в числа m₁, m₂...] → [Шифрование: cᵢ = mᵢᵉ mod n]`

---

#### 2.1. Разбиение сообщения на блоки
Сообщение разбивается на блоки. Каждый блок `m` должен удовлетворять условию `m < n` (размер которых в битах меньше размера модуля `n`). 
Например, для `n = 3233` (12 бит) максимальный размер блока — 12 бит (числа до 4095).  

Сообщение кодируется в числовой формат (ASCII, UTF-8):  
`"RSA"` → ASCII-коды: `'R'=82, 'S'=83, 'A'=65`
Блоки: [82, 83, 65]

---

#### 2.2. Вычисление шифртекста для каждого блока
Используется публичный ключ `(e, n)`.  
```
cᵢ = mᵢᵉ mod n
```

**Пример шифрования:**: (публичный ключ `(e, n) = (17, 3233)`)  
Используется алгоритм быстрого возведения в степень.  
- **блок `m = 82`**:  
    ```
    82¹⁷ mod 3233:
    82² = 6724 mod 3233 = 258
    82⁴ = (6724)² mod 3233 = 1904
    ...
    ⇒  c = 82¹⁷ mod 3233 = 1859
    ```
- **блок `m = 83`**:  
    ```
    c = 83¹⁷ mod 3233 = 2680
    ```
- **блок `m = 65`**:  
    ```
    c = 65¹⁷ mod 3233 = 2790
    ```

**Итоговый шифртекст**:  
```
[1859, 2680, 2790]
```

---

### Этап 3. Расшифрование сообщения  
**Блок-схема**:  
`[Шифртекст c₁, c₂...] → [Расшифрование: mᵢ = cᵢᵈ mod n] → [Сборка блоков] → [Исходное сообщение]`

---

#### 3.1. Расшифрование каждого блока
Используется приватный ключ `(d, n)`.  
```
mᵢ = cᵢᵈ mod n
```

**Пример расшифрования**: (приватный ключ `(d, n) = (2753, 3233)`)  
Используется Китайская теорема об остатках (CRT):
```
m ≡ c^d mod p × q
```

- **блок `c = 1859`**:  
    ```
    m = 1859^2753 mod 3233 = 82
    ```
- **блок `c = 2680`**:  
    ```
    m = 2680^2753 mod 3233 = 83
    ```
- **блок `c = 2790`**:  
    ```
    m = 2790^2753 mod 3233 = 65
    ```


**Расшифрованные блоки**:  
```
[82, 83, 65]
```

---

#### 3.2. Сборка блоков в исходное сообщение
Числа преобразуются в символы по выбранной кодировке и объединяются.  

**Пример**:  
```
82 → 'R', 83 → 'S', 65 → 'A'
Результат: "RSA"   ⇒   Сообщение: "RSA" 
```

---

#### Итог
- **Зашифрование**: Сообщение "RSA" разбивается на блоки `[82, 83, 65]` и шифруется в `[1859, 2680, 2790]`.  
- **Расшифрование**: Шифртекст преобразуется обратно в исходные числа и собирается в строку `"RSA"`.  
- **Криптостойкость**: Даже для коротких сообщений алгоритм гарантирует безопасность при условии правильной генерации ключей.

---

### Полный цикл с разбиением на блоки

| Шаг                    | Данные                   | Действие                                              |
|------------------------|--------------------------|-------------------------------------------------------|
| **Исходное сообщение** | `"RSA"`                  | Разбито на 3 символа: `'R'`, `'S'` и `'A'`.           |
| **Кодирование**        | `[82, 83, 65]`           | Каждый символ преобразован в ASCII-код.               |
| **Шифрование**         | `[1859, 2680, 2790]`     | Каждый блок зашифрован отдельно.                      |
| **Дешифрование**       | `[82, 83, 65]`           | Блоки расшифрованы с использованием приватного ключа. |
| **Сборка**             | `"RSA"`                  | Числа преобразованы обратно в символы.                |

## IV. Описание работы программы "RSA Encryption/Decryption Tool"

Программа написана на языке **Python** и реализует криптографический алгоритм RSA для асимметричного шифрования данных. 

**Основные возможности:**  
- Генерация ключевой пары (публичный/приватный ключи) с настраиваемыми параметрами.  
- Шифрование данных открытым ключом.  
- Расшифрование данных приватным ключом.  
- Поддержка текстовых и бинарных данных.  
- Сериализация ключей в PEM-формате.  

**Алгоритм соответствует современным стандартам:**
- Минимальный размер ключа: **2048 бит**.  
- Рекомендуемые экспоненты: **3, 17, 65537**.  
- Проверка простых чисел через тесты **Миллера-Рабина** и **Ферма**.  

---

### Структура кода  
#### Класс `RSA`
- **Генерация ключей**  
  - `generate_keys()`: Создает ключевую пару на основе простых чисел.  
  - `get_prime_number()`: Генерирует простое число заданного размера (от 128 бит).  
- **Шифрование/Расшифрование**  
  - `encrypt()`: Разбивает данные на блоки, дополняет их и шифрует.  
  - `decrypt()`: Расшифровывает блоки и удаляет дополнение.  
- **Сериализация**  
  - `key_to_pem()`: Конвертирует ключ в PEM-формат (Base64 с заголовками).  
  - `pem_to_key()`: Извлекает ключ из PEM-формата.  
- **Дополнение данных**  
  - `pad_data()`: Добавляет заголовок длины и случайные байты.  
  - `unpad_data()`: Восстанавливает исходные данные.  

#### Интерфейс пользователя
- **Интерактивный режим** 
  - `interactive_mode()`: Пошаговый ввод данных через консоль.  
- **Режим командной строки** 
  - `arguments_mode()`: Запуск программы с использованием аргументов командной строки.  

#### Точка запуска
- Функция `main()`: Определяет, какой режим запуска использовать (интерактивный, если аргументы отсутствуют, или командный с параметрами).  

---

### Генерация ключевой пары
1. **Генерация простых чисел**  
   - Программа создает два случайных простых числа `p` и `q` длиной от 128 бит каждое.  
   - Для проверки простоты используются:  
     - **Тест Миллера-Рабина** (32 раунда) — вероятностная проверка.  
     - **Улучшенный тест Ферма** — исключает числа Кармайкла.  
   - Числа проверяются на минимальную разницу (`|p - q| > 2^(n/2 - 100)`), чтобы избежать атак факторизации.

2. **Расчет параметров**  
   - **Модуль**: `n = p * q`.  
   - **Функция Эйлера**: `φ(n) = (p-1)(q-1)`.  
   - **Открытая экспонента**: Выбирается из списка `[3, 17, 65537]`.  
   - **Закрытая экспонента**: Вычисляется как `d ≡ e⁻¹ mod φ(n)` через расширенный алгоритм Евклида.

3. **Сериализация ключей**  
   - Ключи сохраняются в **PEM-формате** с Base64-кодированием:  
     ```text
     -----BEGIN RSA PUBLIC KEY-----
     [Base64-данные]
     -----END RSA PUBLIC KEY-----
     ```
   - Структура данных:  
     ```
     [4 байта: длина e][e][4 байта: длина n][n]
     ```

---

### Шифрование данных
1. **Подготовка данных**  
   - Текст кодируется в байты (UTF-8).  
   - Данные разбиваются на блоки размером `(длина n в байтах) - 4`.  
     *Пример*: Для `n = 2048 бит` (256 байт) размер блока — 252 байта.

2. **Дополнение блоков**  
   Каждый блок форматируется как:  
   ```
   [4 байта: длина данных][данные][случайные байты]
   ```  
   - Случайные байты генерируются через `os.urandom()` для защиты от шаблонных атак.

3. **Преобразование и шифрование**  
   - Блок конвертируется в целое число `m`.  
   - Вычисляется шифротекст: `c = m^e mod n`.  
   - Результат преобразуется в байты фиксированной длины (равной размеру `n`).

4. **Сборка шифротекста**  
   - Все зашифрованные блоки объединяются в бинарный файл или строку Base64.

---

### Расшифрование данных
1. **Проверка входных данных**  
   - Длина шифротекста должна быть кратна размеру модуля `n`.  

2. **Разбиение на блоки**  
   - Шифротекст делится на блоки размером `(длина n в битах + 7) // 8` байт.

3. **Преобразование и расшифрование**  
   - Каждый блок интерпретируется как целое число `c`.  
   - Вычисляется исходное число: `m = c^d mod n`.  

4. **Удаление дополнения**  
   - Из первых 4 байт извлекается длина исходных данных.  
   - Проверяется корректность длины.  
   - Удаляются случайные байты, сохраняется только полезная нагрузка.

5. **Восстановление данных**  
   - Все блоки объединяются в массив байт.  
   - Данные декодируются в строку (для текста) или сохраняются как файл.

---

### Особенности реализации
#### Безопасность
- **Минимальный размер ключа**: 2048 бит (защита от факторизации модуля `n` методом квадратичного решета).  
- **Рекомендуемая экспонента**: `65537` (оптимальный баланс скорости и безопасности), используются только рекомендованные значения (`3, 17, 65537`).  
- **Проверка простых чисел**: Тест Миллера-Рабина (вероятностный), или Тест Ферма с фильтрацией чисел Кармайкла.  
- **Дополнение данных**: Случайные байты защищают от атак на основе шаблонов.  
- **PEM-формат**: Ключи кодируются в Base64 для удобства и защиты от искажений.  

#### Обработка ошибок
- **Некорректный блок**: При расшифровании проверяется соответствие длины данных в заголовке.  
- **Неверный ключ**: Попытка использования приватного ключа для шифрования вызывает ошибку.

## V. Режимы запуска программы

Программа поддерживает два режима работы: интерактивный (диалоговый) и командный (через параметры). 

---

### Интерактивный режим в консоли

Запуск без параметров:
```shell
python rsa.py
```

**Процесс взаимодействия:**  
1. **Выбор операции**:  
   ```
   Выберите режим работы алгоритма (генерация ключей - [key], зашифровать - [encrypt], расшифровать - [decrypt]): key
   ```  
   - `key`/`k` — генерация ключевой пары.  
   - `encrypt`/`e` — зашифрование данных.  
   - `decrypt`/`d` — расшифрование данных.  

2. **Генерация ключей**:  
   - Указание размера ключа (минимально допустимое значение `2048` бит):
     ```
     Размер ключа (по умолчанию 2048 бит): 4096
     ```  
     **Примечание:** при вводе некорректного значения сработает контроль-предупреждение
   - Выбор открытой экспоненты (разрешено выбрать из списка: `3`, `17`, `65537`):
     ```
     Открытая экспонента зашифрования (по умолчанию 65537): 17
     ```  
     **Примечание:** при выборе экспоненты не из списка сработает контроль-предупреждение
   - Указание путей для сохранения ключей (при указании только имени, ключи будут сохранены в текущей рабочей папке):
     ```
     Файл для публичного ключа (по умолчанию public.key): public.pem  
     Файл для приватного ключа (по умолчанию private.key): private.pem
     ```  

3. **Зашифрование/Расшифрование**:  
   - Выбор источника данных:  
     ```
     Выберите источник данных (текст - [text], файл - [file]): file
     ```  
     - `text`/`t` — Ввод строки для обработки. 
     - `file`/`f` — Указание пути к входяшему файлу с данными.

## VII. Методы криптоанализа криптосистемы RSA

### 1. Атака Винера (малый закрытый ключ)
Эксплуатация уязвимости возникает, когда закрытый ключ **d** имеет недостаточный размер. В RSA выполняется соотношение **ed ≡ 1 mod φ(n)**, где **φ(n) = (p-1)(q-1)**. 
Если **d** слишком мал, то коэффициент **k** в уравнении **ed - kφ(n) = 1** также становится небольшим. Это позволяет аппроксимировать отношение **e/n** как **k/d**, используя непрерывные дроби. 
Алгоритм последовательно генерирует дроби, приближающие **e/n**, и проверяет их на возможность факторизации модуля **n** через решение квадратного уравнения. 
**Для защиты** использовать `d > (¹⁄₃) n^(¹⁄₄)`.

---

### 2. Атака Хастеда (общее сообщение)
Уязвимость проявляется, когда одно и то же сообщение **m** шифруется с **малой открытой экспонентой e** (напр., **e = 3**) для нескольких модулей **n₁, n₂, ..., nₖ**. 
Если злоумышленник перехватит **k ≥ e** шифртекстов, он может использовать китайскую теорему об остатках (CRT), чтобы восстановить **m^e** как целое число, а затем извлечь корень степени **e** для получения исходного сообщения. 
**Для защиты** избегать шифрования одного сообщения **m** с малой **e** для разных модулей. Использовать дополнение сообщений (PKCS#1).

---

### 3. Атака с малой открытой экспонентой (e)
Использование малых значений **e** (например, **3**, **5**) упрощает вычисления, но создает риски, если сообщение **m** не дополняется случайными данными. 
Когда **m^e < n**, шифртекст **c = m^e** не требует операции модуля, и злоумышленник может напрямую вычислить **m = √[e]{c}**. 
**Для защиты** применять стандарты дополнения (OAEP, PKCS#1). Использовать `e ≥ 65537`.

---

### 4. Атака на повторное использование простых чисел
Если два модуля **n₁ = p·q₁** и **n₂ = p·q₂** содержат общее простое число **p**, злоумышленник вычисляет **НОД(n₁, n₂)**, чтобы раскрыть **p**. 
Это позволяет факторизовать оба модуля и вычислить закрытые ключи. 
**Для защиты** генерировать уникальные простые числа для каждого ключа. Проверять `НОД(n₁, n₂)` при использовании нескольких модулей.

## VIII. Реализация атаки Винера на криптосистему RSA (с приведением численных результатов)

### Общее описание
Атака Винера — это криптографическая атака на RSA, которая позволяет восстановить закрытый ключ `d`, если он достаточно мал. 
Атака основана на использовании **непрерывных дробей** для приближения отношения `e/n`, где `e` — открытый ключ, а `n = pq` — модуль RSA. 
Успешность атаки зависит от выполнения условия:  
`d < (1/3) × n^(1/4)`.
Сложность алгоритма определяется количеством подходящих дробей для непрерывной дроби числа `e/N`. То есть число `d` восстанавливается за линейное время от длины ключа.

---

### Математическое обоснование
В RSA выполняется соотношение: `ed ≡ 1 mod φ(n)`, где `φ(n) = (p-1)(q-1)`.  
Это можно переписать как: `ed - kφ(n) = 1`, где `k ∈ ℤ`. Если `d` небольшое, то `k` также будет небольшим.  
Тогда: `e/φ(n) ≈ k/d`. Так как `φ(n) ≈ n`, получаем: `e/n ≈ k/d`.  
Алгоритм непрерывных дробей позволяет найти дробь `k/d`, близкую к `e/n`, что в итоге используется для восстановления `d`.

---

### Основные параметры
- **Модуль**:  
  `n = p × q`  
- **Функция Эйлера**:  
  `φ(n) = (p-1)(q-1)`  
- **Открытый ключ**:  
  `e` (выбирается взаимно простым с `φ(n)`)  
- **Закрытый ключ**:  
  `d ≡ e⁻¹ mod φ(n)`  
- **Условие уязвимости**:  
  `d < (1/3) × n^(1/4)`.
- **Точность аппроксимации**:  
  Подходящая дробь `k/d` должна быть достаточно близка к `e/n`.

---

### Алгоритм атаки
1. **Разложение `e/n` в непрерывную дробь**
    ```
    e/n = a₀ + 1/(a₁ + 1/(a₂ + 1/(…)))
    ```  
    Коэффициенты `a₀, a₁, a₂, …` вычисляются через алгоритм Евклида.  


2. **Вычисление подходящих дробей**  
    Для каждого шага непрерывной дроби вычисляется подходящая дробь `kᵢ/dᵢ`, которая приближает `e/n`.  
    Используя **Рекуррентные формулы**:, для коэффициентов `[a₀; a₁, a₂, …]` вычисляются дроби:  
    ```
    k₋₂ = 1, k₋₁ = 0, d₋₂ = 0, d₋₁ = 1
    kᵢ = aᵢ × kᵢ₋₁ + kᵢ₋₂  
    dᵢ = aᵢ × dᵢ₋₁ + dᵢ₋₂
    ```  


3. **Исследование кандидатов `dᵢ`**  
   Для каждой подходящей дроби `kᵢ/dᵢ`:  
   - Предполагаем, что `d = dᵢ`.  
   - Вычисляем `φ(n) = (edᵢ - 1)/kᵢ`.  
   - Решаем квадратное уравнение `x² - (n - φ(n) + 1)x + n = 0`, и получаем пару корней `(pᵢ, qᵢ)`
   - Если корни `pᵢ` и `qᵢ` целые, и выполняется равенство `N = pᵢ × qᵢ`, то `dᵢ` — корректный закрытый ключ
   - Если условие не выполняется или не удалось найти пару корней `(pᵢ, qᵢ)`, то необходимо исследовать следующую подходящую дробь `kᵢ₊₁/dᵢ₊₁`

---

### Пример числового расчета атаки Винера (для открытого ключа `⟨e,n⟩ = ⟨24797, 124691⟩`)

1. **Разложение `e/n` в непрерывную дробь**  
     Выполняем последовательное деление для `e = 24797` и `n = 124691` с помощью **Алгоритма Евклида**:
        
     | Шаг | Делимое (n) | Делитель (e) | Частное (q) | Остаток (r) |
     |-----|-----------|-------------|-------------|-------------|
     | 1   | 124691    | 24797       | 5           | 706         |
     | 2   | 24797     | 706         | 35          | 87          |
     | 3   | 706       | 87          | 8           | 10          |
     | 4   | 87        | 10          | 8           | 7           |
     | 5   | 10        | 7           | 1           | 3           |
     | 6   | 7         | 3           | 2           | 1           |
     | 7   | 3         | 1           | 3           | 0           |

     Из столбца **Частное (q)** получаем **Коэффициенты непрерывной дроби**:  `[0, 5, 35, 8, 8, 1, 2, 3]`, 
     которые станут основой для построения подходящих дробей.  


2. **Вычисление подходящих дробей**  
    Вычисляем первые 2 подходящие дроби используя **Рекуррентные формулы**:  
    ```
    kᵢ = aᵢ × kᵢ₋₁ + kᵢ₋₂
    dᵢ = aᵢ × dᵢ₋₁ + dᵢ₋₂
    ```
   
    | Шаг | aᵢ | kᵢ                 | dᵢ                 | Дробь |
    |-----|----|--------------------|--------------------|-------|
    | 0   | 0  | k₀ = 0×1 + 1 = 1   | d₀ = 0×0 + 1 = 1   | 0/1   |
    | 1   | 5  | k₁ = 5×1 + 0 = 5   | d₁ = 5×1 + 1 = 6   | 1/5   |

    Подходящие дроби аппроксимируют `e/n`. Первая значимая дробь `1/5` уже содержит кандидата `d = 5`.


3. **Исследование кандидата `d = 5`**
    - Вычислим `φ(n) = (e × d - 1) / k = (24797 × 5 - 1) / 1 = 123984`
    - Решаем квадратное уравнение для `φ(n) = 123984, n = 124691`
      ```
      x² - Sx + n = 0, где S = n - φ(n) + 1.
      S = n - φ(n) + 1 = 124691 - 123984 + 1 = 708
      x² - 708x + 124691 = 0
      ```
    - Находим **Дискриминант** для `S = 708, n = 124691`:  
      ```
      D = S² - 4n
      D = 708² - 4×124691 = 501264 - 498764 = 2500  
      √D = √2500 = 50
      ```
      Поскольку `√D = 50` (целое число) → **корни целые** `p` и `q` целые → атака успешна

    - Определяем **Корни** `p` и `q`:  
      ```
      x = (S ± √D)/2
      x₁ = (708 + 50) / 2 = 379  
      x₂ = (708 - 50) / 2 = 329
      ```

    - **Проверка** найденных корней `p = 379` и `q = 329`:
      Проверяем корни по формуле модуля `n = p × q = 379 × 329 = 124691` → совпадает с исходным модулем


3. **Итог**
- **Восстановленный закрытый ключ**: `d = 5`
- **Факторизация модуля**: `n = 379 × 329`
- **Условие уязвимости**: `d < 6.26` → выполнено.

---

**Заключение**:  
Дискриминант `D = (n - φ(n) + 1)² - 4n` — ключевой индикатор успешности атаки.
Если `D` — полный квадрат, корни `p` и `q` целые, RSA-модуль `n` факторизован → атака успешна.  
Если `D` не является квадратом целого числа → кандидат `d` отбрасывается.  
Проверка целостности `D` позволяет быстро определить, верны ли восстановленные `φ(n)` и `d`.

### Шаг 1. Проверка чисел `p = 139` и `q = 197` на простоту с помощью теста Ферма

**Алгоритм (тест Ферма):**  

**Вход:** проверяемое число `n`, и число итераций `k`  
**Выход:** ответ на вопрос "Является ли проверяемое число `n` простым? **Да** - простое, или **Нет** - составное"
1. В цикле для `i ∈ [1, k]` выполняем операции проверки:  
   - Выбираем случайное число `a` из интервала `[2, ..., n - 1]`  
   - Вычисляем `r = aⁿ⁻¹ (mod n)` (через быстрое возведение в степень)
   - Если `r ≠ 1` → то возврат `n - составное`  
2. Возврат `n - предположительно простое`
